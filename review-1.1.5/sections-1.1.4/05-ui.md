# 05 - UI review (FullView, Controls, Theme, widget rendering in AppCtx)

Scope: src/Ui/FullView*.cs (Overview, Settings, Pins, Learn, Guide, Procs, Tools, Link, Wifi, Inside, Paint), Controls.cs, Theme.cs, Evidence.cs, AppCtx.cs (widget, tray, hotkey). Static review only; Windows-only behaviour reasoned from WinForms/.NET 4.8 and Win32 semantics.

Overall: GDI hygiene is good. Fonts are created once, nearly every Brush/Pen/StringFormat/GraphicsPath is in a `using`, widget bitmaps and HBITMAP/DC are released, and cached chart bitmaps are disposed on key change and on close. I found no per-paint GDI leak. Every BeginInvoke from a background task is wrapped in try/catch, Clipboard calls are wrapped, and knowledge parsing is tolerant: a missing key reads as "", and malformed ladder segments are skipped. The real problems are in multi-monitor/DPI behaviour, layout at small sizes or high scaling, keyboard and screen-reader access, and a few interaction details.

## CONFIRMED

### C1 [High] Global hotkey Ctrl+Alt+A takes over AltGr+A, so some keyboard layouts can no longer type a letter
`src/Ui/Controls.cs:403`
```csharp
Ok = Native.RegisterHotKey(Handle, 1, 0x0001 /*ALT*/ | 0x0002 /*CTRL*/ | 0x4000 /*NOREPEAT*/, (uint)Keys.A);
```
- **What happens:** Windows treats AltGr as Ctrl+Alt. A user on the Polish (Programmers) layout presses AltGr+A to type "ą", or a Hungarian/other-layout user types the character on AltGr+A. RegisterHotKey eats the keystroke system-wide, so the character never reaches any app and the engineer view toggles open and closed instead. This happens in every app for as long as AdeeboMeter runs, and it starts with Windows by default. Ctrl+Alt+A is also the screenshot hotkey of WeChat/QQ/TIM; whoever registers first wins.
- **Fix:** Make the hotkey configurable and include an "Off" choice in Settings. Default to a combination that AltGr cannot produce, such as Win+Shift+A or Ctrl+Shift+Alt+A. At minimum, skip registration when the active input locale has AltGr characters on A (check with `VkKeyScanEx` for Ctrl+Alt).

### C2 [Medium] The corner widget shows over full-screen presentations and video, and is captured by screen sharing
`src/AppCtx.cs:293-341` (OnUi) and `src/Ui/Controls.cs:30-57` (LayeredForm)
- **What happens:** The widget is TOPMOST and re-asserts HWND_TOPMOST on every Present and every 30 s. OnUi never calls `SHQueryUserNotificationState` or checks for a full-screen window. `CanNotify()` gates only balloon alerts. Scenarios:
  - **PowerPoint slideshow or full-screen YouTube:** WindowOver sees a window over the zone and folds the widget into the chip, but the chip still draws at 20-100% on top of the projected slide.
  - **When there is a problem:** with Level>0 the card stays open, so a large card sits on the presentation.
  - **Teams/Zoom screen share:** layered topmost windows are captured. Viewers see the widget, and hovering opens the detail card, which shows "Top apps by memory" with process names.
- **Fix:** Hide the widget (Vanish) while `SHQueryUserNotificationState` returns QUNS_BUSY, QUNS_RUNNING_D3D_FULL_SCREEN, QUNS_PRESENTATION_MODE or QUNS_APP. Call `SetWindowDisplayAffinity(widget.Handle, WDA_EXCLUDEFROMCAPTURE /*0x11*/)` on Windows 10 2004 and later, for both widget and detailWin.

### C3 [Medium] Main section tabs and fixed button bars clip off the right edge on common small screens and high scaling
`src/Ui/FullView.cs:139` (tabs), `:213` (health bar), `:261` (procs bar), `src/Ui/FullView.Inside.cs:27` (Inside mode chips). All are `FlowLayoutPanel { WrapContents = false }`.
- **What is handled and what is not:** Only `subTabs` (FitTabs) and `chips` (the chips.Resize handler) adapt. The 8 section tabs (Overview ... Learn, about 760 px at 100%, plus badges such as "3 new" and "REC") do not wrap, do not shorten and do not scroll. The left pane is the window width minus the side column (300-390*S) minus padding.
- **Estimated breakage points:**
  - Section tabs: 1366x768 at 125% (left pane about 916 px against about 955 px of tabs), 1280x800 at 125%, and 1920x1080 at 175%. "Time machine" and "Learn" are cut off or missing; they stay reachable only through Ctrl+K.
  - Inside Windows chips: search box 240 + 5 chips is about 890 px at 100%, so "Deep dives" and "Starts with Windows" clip even at 1366x768 at 100%.
  - Health bar: "What can AdeeboMeter see here?" clips at 125% on 1366 px.
  - These widths are estimates from the font sizes; the logic gap itself is confirmed.
- **Fix:** Use WrapContents=true with AutoSize for these bars, as destBar and hb2 already do. Alternatively apply the FitTabs short-name approach to `tabs` and add overflow (a "More" chip, or horizontal scroll).

### C4 [Medium] The Connections list does not scroll with precision touchpads or high-resolution wheels
`src/Ui/Controls.cs:391`
```csharp
sb.Value = Math.Max(0, Math.Min(max, sb.Value - e.Delta / 120 * RowH * 3));
```
- **What happens:** Integer division. Precision touchpads and free-spinning or high-resolution mice send deltas smaller than 120 (for example 8-40). `e.Delta / 120` is then 0, so two-finger scrolling over Connections does nothing on most modern laptops. The other pages use AutoScroll and are unaffected.
- **Fix:** Accumulate the remainder: `wheelAcc += e.Delta; int px = wheelAcc * RowH * 3 / 120; wheelAcc -= px * 120 / (RowH*3);`, or simply `sb.Value - e.Delta * RowH * 3 / 120`.

### C5 [Medium] Painting the Settings page temporarily changes live monitor settings (cross-thread race)
`src/Ui/FullView.Settings.cs:77` (called 3 times on every Settings paint) and `:168-173`
```csharp
static int JobsFor(string preset)
{   int gw = Cfg.GwSec, ...; Cfg.ApplyPreset(preset); int n = Cfg.JobsPerMinute();
    Cfg.GwSec = gw; ... Cfg.Preset = p; return n; }
```
- **What happens:** On every repaint of Settings (every click, scroll and resize), the UI thread briefly writes the Penny, Balanced and Engineer values into the global volatile `Cfg.GwSec/NetSec/WifiSec/AppsSec/Call`. The Monitor background loop reads these fields concurrently. It can see `WifiSec=10` or `GwSec=2` from Engineer, or `NetSec=60` from Penny, and schedule an extra netsh/ping or skip one. A user who chose "Off" (0) for a probe can get one probe sent while scrolling Settings, which matters for an app whose About page promises exactly what leaves the PC.
- **Fix:** Make the job-count calculation pure, for example `static int JobsFor(int gw, int net, int wifi, int apps)` fed from a preset table, and never mutate Cfg to compute it.

### C6 [Medium] Import settings wipes your pinned destinations before it knows the file is valid
`src/Ui/FullView.Settings.cs:384`
```csharp
int n = 0; Cfg.Pins.Clear();
foreach (var line in File.ReadLines(d.FileName).Take(200)) { ... }
Cfg.Save(); ... settingsNote = "Loaded " + n + " settings.";
```
- **What happens:** The dialog offers "All files". If the user picks the wrong file (a .txt, or an older export without `pin=` lines), the pins are cleared and then persisted by `Cfg.Save()`, and the page reports "Loaded 0 settings." If an IOException occurs mid-read, pins are already cleared in memory and are saved on the next settings change.
- **Also:** `widget` and `theme` are in `Cfg.Known` and are counted in `n`, but `Cfg.Read` has no case for them, so they are reported as loaded yet never applied.
- **Fix:** Parse into a temporary list first. Clear and replace pins only if the file contained at least one known key (or at least one `pin=`). Apply `theme` through `Cfg.SetTheme` and `widget` through the AppCtx state. Count only keys that were applied.

### C7 [Medium] "Delete all saved history now" deletes on one click with no confirmation
`src/Ui/FullView.Settings.cs:117-121`
- **What happens:** A painted red text link sits directly under the Settings rows, with a hit area 220*S x 22*S. One stray click while scrolling with click-drag permanently deletes up to 90 days of history. There is no confirmation and no undo.
- **Fix:** Confirm with a MessageBox (Yes/No, default No), or a two-step "Click again to delete" state that expires after 3 s.

### C8 [Medium] Esc closes the whole engineer view while you are typing in a text box
`src/Ui/FullView.cs:300-305`
```csharp
if (e.KeyCode == Keys.Escape) {
    if (tbSearch != null && tbSearch.Box.Focused && tbSearch.Box.Text != "") return;
    ... Close();
```
- **What happens:** Only the Toolbox search box is exempt (KeyPreview=true). The user types a host in "Check a destination", the guide box, Find a process, the walk-test room name, Learn search or Connections filter, then presses Esc to clear it (a common habit). The view closes, and any running check or results, walk-test spots and live capture are discarded. Minimise, or Win+D ("Show desktop"), does the same through `Resize -> Close` (line 331).
- **Fix:** If `ActiveControl` is a TextBoxBase with text, clear it and set `e.SuppressKeyPress`. Only close when focus is not in a non-empty text box. Consider not tearing down running work on Win+D minimise.

### C9 [Low-Medium] Cover detection uses a fixed 264x300 zone, so the "Bigger widget" card and tall cards are not folded
`src/AppCtx.cs:286-291`
```csharp
int w = (int)(264 * Draw.S), h = (int)(300 * Draw.S);
```
- **What happens:** With Bigger widget the card is 343*S wide and about 330-420*S tall. With a Teams call strip and a two-line headline, even the normal card is taller than 300*S. A window that overlaps only the upper or left part of the card is not detected, so the card stays open, topmost, over that window's content. The `near` fast-poll zone is wrong in the same way.
- **Fix:** Derive the zone from `widget.Placed` (when non-empty), or from the last rendered bitmap size, instead of constants.

### C10 [Low-Medium] Font.GetHashCode is used as the measure-cache key, and on .NET Framework it ignores the font family
`src/Ui/Theme.cs:212`
```csharp
string key = f.GetHashCode().ToString(...) + "|" + width + "|" + t;
```
- **Why it collides:** In .NET Framework, `Font.GetHashCode()` mixes only style, GdiCharSet and `(uint)fontSize` (truncated). These pairs collide:
  - fBody (Segoe UI 12.5 Regular) and fBodyB (Segoe UI Semibold 12.5 Regular) at any scale.
  - fSmall (11) and fMono (11.5) at 100%.
  - fSmall and fMonoS (13.75 and 13.125, both truncating to 13) at 125%.
- **What happens:** The same string measured with both fonts returns the first font's size. Wrapped Semibold or monospace text can get a height that is too small, so the last line is clipped or the next element overlaps.
- **Fix:** Key on `f.Name + f.SizeInPoints + f.Style`, or keep a `Dictionary<Font, ...>` per font (reference identity, because the fonts are singletons).

### C11 [Low] The capture status always says "30 s" even when Sniff is set to 60 s
`src/Ui/FullView.cs:851`: `"Listening in for 30 s on "` is hard-coded while dumpcap is given `-a duration:" + Cfg.SniffSec`. Similarly, the Live capture page label (`FullView.cs:240`) builds "... after N min" once at view creation and goes stale after a Settings change until the view is reopened. **Fix:** use `Cfg.SniffSec`, and refresh the label in ShowTab.

### C12 [Low] Save failures are silent
`src/Ui/FullView.Tools.cs:47`: an IOException or UnauthorizedAccessException from SaveText (read-only folder, file open in Notepad, OneDrive placeholder) is only logged, and the user sees nothing. The same applies to the Clipboard copy links in `Paint.cs:161` and `Tools.cs:60`: on ExternalException (clipboard locked by RDP or another app) "Copied ✓" simply never appears. **Fix:** show a short status ("Couldn't save: ...") in the same place the "Copied ✓" text appears.

### C13 [Low] Detail card and painted rows can be taller or wider than their space
- `src/Ui/Theme.cs:363-402` (DetailCard): it is placed at `wa.Bottom - m - H` and left of the widget, with no clamp to the screen. On a short screen (landscape tablet at 200%) the top goes off-screen. On a narrow work area it can spill onto the monitor to the left. **Fix:** clamp to `WidgetScreen().WorkingArea`.
- `TipWin.ShowAt` (`Controls.cs:466-478`) clamps only x/y. A long explanation with h > work area is cut off at the bottom.
- Unclipped `DrawString(text, font, brush, x, y)` with user or network data: `Overview.cs` netLine (SSID up to 32 bytes plus adapter speed), the walk-test verdict (`Wifi.cs`, room names), the dest title "RESULT · <long host>", the footer (right text overlaps the left stats when the live capture suffix is shown at 980*S width). These run under neighbouring content or off the card. **Fix:** draw into a RectangleF with EllipsisCharacter, as most other rows already do.

### C14 [Low] `Draw.Trunc` cuts surrogate pairs
`src/Ui/Theme.cs:226` uses `s.Substring(0, n - 1) + "…"`. Emoji or astral-plane SSIDs, pin names (`Pins.cs`, Trunc 28), adapter names (Trunc 50) and DetailCard values (Trunc 30) can end in a lone high surrogate, which renders as a box glyph. **Fix:** step back one character if `char.IsHighSurrogate(s[n-2])`.

### C15 [Low] The tray tooltip is rewritten on every render once it exceeds 63 characters
`src/AppCtx.cs:356-357`: `if (tray.Text != tip) tray.Text = tip.Length > 63 ? tip.Substring(0,63) : tip;`. The comparison uses the untruncated `tip`, so a tooltip over 63 characters sends NIM_MODIFY every second while the card is open. Harmless today because Chip is short, but compare against the truncated string.

### C16 [Low] Settings and Procs pages do disk or process I/O inside Paint
- `Settings.cs:117`: `History.Days()` (directory enumeration) and `History.Bytes()` run on every Settings repaint.
- `Inside.cs:203`: `Native.ExePath(p.Pid)` runs on every repaint of the Inside info pane.
- `InsideItems()` in "boot" mode calls `Process.GetProcessById(...).StartTime` for 15 entries on every list paint.
- Procs and Changes lists paint every row, not only visible ones, with two `Explain.Find` calls per row per paint.
- Effect: a sluggish UI on slow disks or AV-scanned systems. The paint watchdog logs "slow paint" but nothing prevents it. **Fix:** cache these per refresh tick.

### C17 [Low] Changes chart bitmap is not redrawn after reloading the same day
`src/Ui/FullView.Paint.cs:273-279`: the key is `yyyyMMdd|w|dark`. Clicking "Today" again reloads `histData`, but the key is unchanged, so the cached chart from the first render is shown. Today's chart freezes at the first time it was opened in this view. **Fix:** include `histData` identity or a load timestamp in `histKey`, or null `histBmp` in the picker's Act.

## SUSPECTED (need a Windows box to confirm)

### S1 [Medium] Mixed-DPI multi-monitor: blurry widget and wrong cover detection
- `src/Program.cs:74` calls `SetProcessDPIAware()` (system-aware only), and `Draw.S` is fixed once in `AppCtx` ctor (`Draw.Init` returns early on later calls).
- On a second monitor with a different scale, or after the user changes the scale without signing out, DWM bitmap-stretches the whole UI and the layered widget, so text is blurry. This persists for days because the app autostarts.
- Worse, `WindowOver` (`AppCtx.cs:376`) prefers `DwmGetWindowAttribute(DWMWA_EXTENDED_FRAME_BOUNDS)`. That returns physical, DPI-unvirtualized coordinates, while `Zone()` and `Screen.WorkingArea` are virtualized for a system-aware process. On a monitor whose DPI differs from the system DPI, windows are judged to cover or not cover the corner incorrectly: the card stays open over a window, or folds when nothing is there.
- **Fix:** Opt in to PerMonitorV2 (app.manifest dpiAwareness plus `<System.Windows.Forms.ApplicationConfigurationSection><add key="DpiAwareness" value="PerMonitorV2"/>` in app.config for .NET 4.7+). Recompute `Draw.S` per monitor and recreate fonts on WM_DPICHANGED. Until then, use `GetWindowRect` (virtualized) consistently with the zone, or `PhysicalToLogicalPointForPerMonitorDPI`.

### S2 [Medium] Auto-scroll oscillation on long painted pages
`Need()` (`Inside.cs:230`) and the same pattern in every Paint* method set `AutoScrollMinSize` from inside Paint. Width `w` is derived from `ClientSize.Width`, which shrinks by the scrollbar width when the vertical bar appears. When content height is within about one wrapped line of the client height, the following can repeat at specific window sizes:
1. The scrollbar appears and the width narrows.
2. More lines wrap and the content gets taller.
3. Later, the bar is no longer needed and disappears.
4. The width widens, fewer lines wrap, and the content gets shorter.
The result is continuous flicker and CPU use. This applies to Settings, About, Guide, Learn info, Link and the other pages. **Fix:** compute layout width as `ClientSize.Width - SystemInformation.VerticalScrollBarWidth` always (reserve the bar), or keep AutoScroll's vertical bar always visible.

### S3 [Medium] Widget re-claims TOPMOST over the tray context menu and toasts
`Controls.cs:57` sets HWND_TOPMOST on every Present. While Level>0 the card is open and redrawn every second. The tray context menu ("Exit AdeeboMeter" and the rest) and Windows toasts open in exactly the same bottom-right region. The widget can be raised above the open menu, hiding items. Clicks pass through, but the user cannot see what they are clicking. With a bottom auto-hide taskbar, the work area is the full screen, so the widget also sits over the revealed taskbar clock and tray, including AdeeboMeter's own icon. **Fix:** skip the TOPMOST re-assert while the tray menu is open (`menu.Opened` / `menu.Closed`). With auto-hide (`SHAppBarMessage(ABM_GETSTATE)`), offset by the taskbar's revealed thickness.

### S4 [Medium] Second launch opens the view behind other windows
A second launch (double-click the exe or shortcut while already running) calls `Single.AskRunningToOpen()`, and the running instance calls `full.Activate()` from a BeginInvoke (`AppCtx.cs:161`). The background process does not have foreground rights, and the launching process never calls `AllowSetForegroundWindow(ASFW_ANY)` before signalling. The result is usually a flashing taskbar button instead of a visible window, so the user thinks it did nothing. Tray click and the hotkey are fine, because WM_HOTKEY and tray input grant foreground rights. **Fix:** in the second instance, call `AllowSetForegroundWindow(-1)` before `o.Set()`.

### S5 [Low-Medium] Watchdog timer callback can crash the process during close
`FullView.cs:76`: inside a `System.Threading.Timer` callback, `BeginInvoke` is guarded only by `catch (InvalidOperationException)`. If the handle is destroyed between the `IsHandleCreated` check and `MarshaledInvoke` touching `Handle`, an `ObjectDisposedException` escapes. Unhandled exceptions in threadpool timer callbacks terminate the process, writing Crash.txt, and the user gets the "closed unexpectedly" balloon next start. The race is tiny but runs every second. The callback can also run after `watchdog.Dispose()` (an in-flight callback). **Fix:** `catch (Exception)`.

### S6 [Low] Quitting from the tray while a modal dialog is open disposes the view under the dialog
Quit from the tray while the Ctrl+K palette, Save or Export dialog is open (`ShowDialog(this)`) calls `full.Close(); full.Dispose()` inside the nested modal loop. When ShowDialog returns, code continues on a disposed form, for example `pal.Chosen()` calling ShowTab or `settingsCanvas.Invalidate`. ObjectDisposedException then goes to ThreadException, which only logs it. **Fix:** check `IsDisposed` after every ShowDialog, or close open owned forms first in Quit.

### S7 [Low] Fonts: Segoe UI Variable under GDI+, and missing CJK/emoji glyphs
`Draw.Fam` (Theme.cs:172-184) picks "Segoe UI Variable Text/Display" on Windows 11. GDI+ has only partial support for variable-font named instances. Bold is requested as FontStyle.Bold on a variable family, which may be synthetically emboldened (smeared) rather than using the real wght axis. GDI+ `DrawString` also has weaker font fallback than DirectWrite, so CJK process descriptions, SSIDs or window titles and emoji may render as boxes. On Windows 10, falling back to Segoe UI is fine.

### S8 [Low] `Screen.PrimaryScreen` can be null
In a disconnected RDP session, or when all displays power down on some GPUs, `Screen.PrimaryScreen` can return null on .NET Framework. `WidgetScreen().WorkingArea` then throws a NullReferenceException in OnUi every 250 ms. It is caught, but writes "ui: ..." to the log 4 times a second until the log rotates at 256 KB, losing useful history. **Fix:** null-guard, and rate-limit the OnUi error log the way `Present` already does.

### S9 [Low] Bidi and zero-width characters in SSIDs and process metadata
SSIDs (neighbour list, netLine, LOOK-ALIKE NETWORKS) and exe FileDescription/CompanyName ("Describes itself as", "Publisher") are drawn raw. U+202E (RLO) or zero-width joiners let a nearby AP or a malicious exe make "(you)" appear on the wrong row, or make a name look like "Microsoft Windows". The look-alike detector is the place this matters. **Fix:** strip or escape Cf-category characters (and show them as `‮`) before display and comparison.

### S10 [Low] Holding Enter or Space on a toggle button repeats the action
`PillButton.OnKeyDown` (`Controls.cs:124`) fires Click on every auto-repeat KeyDown. Holding Enter on "Pin", "Start live capture" or the theme switch toggles it many times; Live capture starts and kills tshark repeatedly. **Fix:** act on KeyUp, or ignore repeats (track a key-down flag).

## ACCESSIBILITY

### A1 [High] Almost all content and actions are custom-painted and invisible to screen readers and the keyboard
The verdict, path dots, every result card, the Settings segmented controls, About links, Overview tiles and "Investigate" chips, Guide problem cards, Learn list, Procs list, Inside list, pin table rows, Dest "Copy as text"/"Save...", walk-test Rename/Remove, "Find my switch port" and "Delete all saved history now" are all drawn on `DB` panels with `Act()` hit-rects. That means:
- **No accessible objects:** Narrator/NVDA read nothing; the panels have no AccessibleName and no child IAccessible.
- **Mouse only:** these actions cannot be reached or triggered with Tab/Enter. Settings in particular cannot be changed from the keyboard at all.
- Only `tbList` (Toolbox) uses `KeyNav`.

**Fix:** Give each DB an `AccessibleObject` subclass that exposes the `acts` and `hints` lists as children (name = drawn text, role PushButton/ListItem, DoDefaultAction = invoke). Add Tab/arrow navigation over `acts` with a painted focus ring. For Settings, real RadioButton-like controls are simplest.

### A2 [Medium] The text boxes have no accessible name
`RoundBox` (`Controls.cs:164-206`) shows the cue in a separate Label overlaid on the TextBox and never sets `Box.AccessibleName`. destBox, Connections filter, Find a process, guideBox, walk-test room, Learn search and Inside search are announced as just "edit". Only Toolbox inputs set it (`Toolbox.cs:468`). **Fix:** `Box.AccessibleName = cue` (or the label) in the RoundBox ctor and Cue setter.

### A3 [Medium] PillButton's accessible name and state go stale
`Controls.cs:114` sets `AccessibleName = text` once. Changes to Text are not reflected:
- "Start live capture" becomes "Stop live capture".
- "Run health check" becomes "Run again".
- The online chip changes to "Online · N min left".
- "Pin" / "Unpin" / "Saved list is full (5)".
- The link tab changes between "Your Wi-Fi" and "Your cable" (short forms when compacted).

So the screen reader announces the wrong action. `Selected` (current tab or filter) and badges ("3 new", "REC", "!") are not exposed either. Disabled Primary buttons draw white text on #AEB8C2, a contrast of about 1.9:1. **Fix:** set `AccessibleName = Text` in OnTextChanged (or rely on UseTextForAccessibility by not setting it). Set AccessibleRole to PageTab/CheckButton for Tab/Chip kinds, override `CreateAccessibilityInstance` to report Selected/Checked, and append the badge to AccessibleDescription. Use a darker disabled colour.

### A4 [Medium] Tab order is backwards (content first, navigation last)
Controls are added fill-first for docking (`FullView.cs:287-293`: pages, then subTabs, then tabs; body, then footer, then pathPanel, then header). WinForms assigns TabIndex in Add order, so Tab visits page content before the section/sub tabs, and the header (Back to corner, Settings, About, Details, theme) comes last. **Fix:** assign TabIndex explicitly after building: header, then tabs, then subTabs, then page bar, then canvas.

### A5 [Medium] High contrast mode is ignored, and status is shown by colour only
`Theme.Apply` uses only hard-coded hex colours. There are no references to `SystemInformation.HighContrast`, `SystemColors` or `UserPreferenceCategory.Accessibility`. In a High Contrast theme the app keeps its own palette, ignoring the user's chosen colours and thicker focus indicators. The tray menu label (Muted #5B6B7C) and the red "Exit" item, drawn on the high-contrast menu background, can become unreadable. The five path dots, the widget chip dot, list status dots and the channel map encode status by red/amber/green colour alone, which deuteranopia cannot separate. **Fix:**
- When `SystemInformation.HighContrast`, map Ink/Card/Line to SystemColors.WindowText/Window/GrayText and Blue to SystemColors.Highlight.
- Do not set ForeColor on tray menu items in High Contrast.
- Add a shape or glyph per level (✓ / ! / ✕) on the dots.

### A6 [Low] The theme switch has no role or state
`ThemeSwitch` (`Controls.cs:410-448`) has AccessibleName "Day or night theme" but the default role (Client) and no checked state. Narrator cannot tell which mode is active. It also always draws its focus ring (no `ShowFocusCues` check). **Fix:** AccessibleRole=CheckButton, report the Checked state when Dark, and check `ShowFocusCues` before drawing the ring.

### A7 [Low] Keyboard gaps in the Connections list, and text scaling is ignored
- `ConnList` has TabStop=true but no IsInputKey or arrow handling: no row selection, no Enter to Sniff, and no accessible rows.
- The "Make text bigger" setting (Settings > Accessibility > Text size) is ignored because all fonts are fixed pixel sizes scaled only by DPI. Consider reading `SystemParameters`/`UISettings.TextScaleFactor` or at least honouring `SystemFonts.MessageBoxFont.Size` ratio.

### A8 [Low] The widget's information is reachable only by mouse hover
The widget is click-through (WS_EX_TRANSPARENT) and opens only on mouse dwell. A keyboard-only user gets only the tray tooltip, truncated to 63 characters ("AdeeboMeter - all quiet"). That is acceptable, but the tooltip could carry the headline (up to 127 characters using `NOTIFYICONDATA` szTip via reflection, or a balloon on Level change). Reachability is otherwise fine: tray left-click, Ctrl+Alt+A, and re-launching the exe all open the view, and "Hide widget" is reversible from the tray.

## Checked and fine (no finding)
- Painting: no per-paint GDI leaks. All Paint* Brush/Pen/StringFormat/GraphicsPath objects are disposed. The `lvBrush` array is disposed in finally. Cached histBmp, weekBmp and replayBmp are disposed on key change and on close. HBITMAP, DC and SelectObject are paired in `LayeredForm.Present`.
- Zero-size client: every rectangle uses `Math.Max(1, ...)` or `Theme.Round` clamps `d >= 1`. ConnList uses `Math.Max(1, Height-HeadH)`. Minimise closes the view, so a width-0 paint does not happen.
- Graphs: `Theme.Spark` handles NaN, all-equal values, one point (returns if fewer than 2) and cap<=0. The day chart guards NaN and negative values and uses a gmax floor of 20. Graphed values are produced with `Math.Max(0.2, dt)`, so no Infinity.
- Opacity: `Fade` is validated by `Pick(51..255)`, so the widget can never go below 20% or disappear. The off-screen widget after unplugging a monitor is handled because `WidgetScreen()` falls back to the primary screen, and the position is recomputed from WorkingArea on every render. Taskbar on the left, top or right is handled through WorkingArea.
- Background work after close: all `BeginInvoke` calls from tasks are inside try/catch. Busy flags (destRunning, healthRunning, toolBusy, guideBusy, linkBusy, whereBusy, insideBusy, pinRunning, switchBusy, walking) prevent duplicate runs. `Investigate.Run` catches internally, so guideBusy is always reset.
- Clipboard: every `Clipboard.SetText` is in try/catch (runs on the STA UI thread). Empty text cannot happen, because ToolText and DestResult.Text always include a header.
- Process.Start of URLs: `Crash.OpenUrl` only allows the project's own GitHub and Pages prefixes. User data goes only into an escaped query string.
- Knowledge packs: `Rec` indexer returns "" for missing keys, lines without ": " are ignored, ladder specs skip malformed segments, and `close` uses TryParse. `Explain.CloseText[e.Close]` would throw for a pack value >= 4, but the current packs use only -1..3. Bound-check it if the packs ever become user-editable.
- Runtime theme switch: `ApplyTheme` and `Recolor` cover TextBox, Label, tagged panels and scrollbars (dark Explorer theme). Painted parts read Theme on every paint.

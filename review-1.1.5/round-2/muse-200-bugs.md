# AdeeboMeter — 198 new bugs (dev-1.1.5, HEAD `a0fbd56`)

Read-only review. Five hunters swept the whole codebase at HEAD `a0fbd56` (dev-1.1.5),
each against an exclusion list of every bug reported in the two reviews delivered
2026-11-12 (`~/workspace/adeebometer-review/known-bugs-excluded.md`). Nothing on that
list is re-reported here. **200 distinct new defects** after merging 15 overlaps
between hunters. One hunter claim was dropped after I checked it myself:
`PathTools.BackHops`'s `+1` is correct as designed — it converts "routers traversed"
to "hop number", which is what its consumers compare against `h.N`. No Critical.
All items are **checked in code** unless marked guessing. The first 100 items
(Highs + Mediums + Medium-Lows + the first 5 Lows) are the ones asked for; the rest
of the Low tail follows, one line each. Numbering note: two Medium entries cover
several defects each (DestCheck Text = 2, the refused-input examples = 3), so the
55 numbered High/Medium entries below cover 58 defects; with the 37 Medium-Lows
and 105 Lows the total is 200.

## High (7)

1. **Every IPv6 UDP receive throws, so IPv6 is dead for SNMP, DNS, NTP, RADIUS, TWAMP, STUN and discovery.** Every receive site passes an IPv4 endpoint to a socket created for the target's family: `Snmp.cs:113` (`Exchange`, `new UdpClient(ep.AddressFamily)` … `Receive(ref from)` with `IPAddress.Any`), `Protocols.cs:151` (NTP), `:262` (SNMP v2c), `:386` (RADIUS), `:461` (TWAMP), `:522` (STUN), `Toolkit.cs:454` (`Query`), `Reach.cs:104,158,230`, `Lab.cs:205`. `Socket.ReceiveFrom` validates the endpoint family and throws `ArgumentException` on mismatch; the catches are `SocketException`-only, so it escapes instead of producing "no answer". SNMP `Request`/`Walk`/`Discover` all go through `Exchange`, so no IPv6 SNMP target can ever answer; `Toolkit.Query` has no `ArgumentException` catch and `Dig` has no try/catch around it, so dig to an IPv6 DNS server aborts the tool. Only NTP survives (`catch (Exception)`), misreported as "no answer". Fix: `new IPEndPoint(a.AddressFamily == InterNetworkV6 ? IPAddress.IPv6Any : IPAddress.Any, 0)`. Trigger: point any of these tools at an IPv6 address. (Exact exception type on .NET Framework 4.8 verified from the runtime source, not run on Windows — guessing on the live run.)
2. **NetBIOS name lookup reads the count and names from the wrong offsets — it never returns a name.** `Reach.cs:175`: `int n = r[56], p = 57;`. The reply is 12-byte header + 38-byte question = 50, then answer pointer(2)+type(2)+class(2)+TTL(4)+RDLENGTH(2) = 12, so the number-of-names byte is at **62** and the names start at **63**. Offset 56 is the high byte of the TTL (0 in practice), so `n` is always 0 and the whole NetBIOS branch is dead. Trigger: run "Name of a device" on a Windows PC that answers NetBIOS.
3. **A single malformed `server` line in games.txt wipes a game's built-in servers.** `Gamer.cs:114` (`Games.ApplyFile`): `if (edited.Add(id)) g.Servers = new List<GameServer>();` runs *before* the validation on the next line, so the first `server|valorant|...` line clears all 11 AWS regions, and if that line is then rejected (bad host/port), the game is left with zero servers and is never measured again. Fix: validate first, clear only when the first *valid* server arrives.
4. **The per-spike context in the match report is never shown.** `Gamer.cs:601` (`GameSession.Report`): `var at = Around(z.T, 0).FirstOrDefault();`, and `Around` (`:583`) requires `Math.Abs((r.T - t).TotalSeconds) <= secs` — with `secs=0` that needs a sub-second-exact timestamp match. Spikes are stamped by `ProbeOne` and evidence rows by `Evidence`, two different `DateTime.Now` calls, so they never match; the "(router X ms, Wi-Fi Y%, traffic …, CPU …)" parenthetical never prints. The same method is used correctly elsewhere with a real tolerance (`FullView.Gamer.cs:224` calls `Around(m.Item1, 15)`).
5. **Culture mismatch crashes the UI on every repaint in non-ASCII-digit locales (ar-SA, fa-IR, …).** Levels are formatted with `CurrentCulture` but parsed with `InvariantCulture`; `int.Parse("٢", InvariantCulture)` throws `FormatException` on the UI thread. Six sites, one root cause: `FullView.Paint.cs:91` (producer `Monitor.AddHealth` formats `lv.ToString(CurrentCulture)` — verified), `:247` (producer `HealthCheck.cs:35`), `:426,441` (producer `LiveCapture.cs:304,333`), `FullView.Inside.cs:128` (keys built as `"pid:" + p.Pid` then parsed Invariant), `Theme.cs:545` (`DetailCard`, producer `Monitor.cs:839`; the widget's hover popup calls it at `AppCtx.cs:376`). Trigger: switch Windows to Arabic (Saudi Arabia), hover the tray widget's "Is it me or the network?" detail. Fix: parse with `CurrentCulture` (or format the level with `InvariantCulture` at the producer).
6. **The self-test assertion "every Traffic Lab sender needs the company-network tick" is vacuous — it passes while senders transmit without the tick.** `SelfTest.cs:906` calls `FullView.LabToolsMissingGate()`, which (`Toolbox.cs:211`) only enumerates `TbLayout` groups whose section is `"lab"`. Senders in other sections are never enumerated: `twamp`, `udpmtu`, `certcmp`/`smtppath`, `radiuslab`, `dnsrace`, `manyports`, `finddev`. `LabGate` only contains `manyports`/`finddev` because someone hand-added them; removing one would not fail the test. Trigger: run `--selftest` on a build where a sender is ungated — it reports PASS. (The underlying gate gap is excluded as known; the *new* finding is the test's false assurance.)
7. **Destination check leaks the typed hostname to public resolvers, bypassing the online-lookups policy.** `DestCheck.cs:494-497` (`CompareDns`): sends the hostname to 1.1.1.1, then 8.8.8.8 on failure, called unconditionally from `RunSteps()` (`:193` and `:206`). Nothing consults `Policy.NoOnline` or `Online.On` — no such reference exists anywhere in `DestCheck.cs`. This contradicts `Online.cs`'s own header ("never the names you type") and means an IT policy `online_lookups = off` does not stop it. Side effect: up to 5 s (2 × 2500 ms) added to every destination check when the public resolvers don't answer.

## Medium (49)

### Protocols and checks

8. **SNMP text values with any non-ASCII character render as hex, and 6-byte ones as a fake MAC.** `Snmp.cs:414-417`: the text test rejects UTF-8 continuation bytes 0x80–0xBF, so any non-ASCII text (sysName "café", "Büro") fails and renders as `0x…` hex; a 6-byte non-ASCII value hits the earlier MAC branch and renders as a bogus MAC.
9. **"Find the port a MAC is on" can return the wrong device's MAC.** `SnmpGear.cs:76` (`FindMac`): the ARP lookup is `kv.Key.EndsWith("." + ip, ...)` where the key is `ifIndex.a.b.c.d`. Searching for `192.168.1.5` matches `10.192.168.1.5` and returns that device's MAC, then the wrong port.
10. **Bandwidth calculator reads "1,000 MB" as 1.0 MB (1000× too small).** `Calc.cs:170` (`Parse2`) does `Replace(',', '.')`, so "1,000" becomes "1.000" → 1.0 MB. The Stack calculator in the same file strips commas as thousands separators. The two calculators disagree on the same input. (Same regex feeds `Size()`, `Speed()`, `Time()` — "1,000 Mbps" → 1 Mbps.)
11. **Number converter reads plain decimals "100000000" and "1000000000" as binary.** `Calc.cs:224-226` (`ParseNum`): the binary branch (`^[01]{9,64}$`) runs *before* the decimal `ulong.TryParse`, so 100 million → 256, 1 billion → 512, and the row says "Read as binary".
12. **Modem signal check mixes upstream power into the downstream range, so a healthy DOCSIS modem is flagged amber.** `IspReport.cs:248-252` (`Modem`): the power regex catches every "Power … dBmV" on the page, including upstream power (normally +35..+55 dBmV), then checks `pwr.Min() >= -7 && pwr.Max() <= 7` (a downstream range). Second half: `unc` (uncorrectable errors) is summed and displayed but ignored by the verdict, so a modem with a million uncorrectable errors still gets a green "signal is in the normal range" row.
13. **The HTTP check echoes a typed user:password into the result rows.** `Reach.cs:80` (`Http`): the status row shows `Draw.Trunc(uri.ToString(), 80)`; unlike `SpeedTest.SafeUrl` it never rejects UserInfo, so `https://user:secret@example.com/api` puts the secret in the rows and in Copy/Save output.
14. **Net-SNMP walk import shows "(too long)" for every 32-bit counter.** `SnmpTools.cs:334` (`FromNetSnmp`): encodes Counter32/Gauge32/Unsigned32 as 8-byte big-endian (`BitConverter.GetBytes(n).Reverse()` where `n` is a `ulong`), but `Snmp.HasNum` allows at most 5 bytes for types 0x41/0x42, so `Snmp.Text` returns "(too long)". Counter64 is fine; Timeticks and minimal INTEGER are fine. Trigger: `--mibtest` on any Net-SNMP walk containing a Counter32/Gauge32.
15. **MTR Duration lies: clamps to 10 minutes, the tool runs 1–60.** `FullView.Toolbox.cs:461` vs `:32`: `Duration("mtr")` does `n = Math.Max(1, Math.Min(10, n))`, but the tool clamps `min` to 1–60 and runs `PathTools.Mtr(dst, hops, min * 60, …)`. Secondary overrun: `PathTools.Mtr` probes hops sequentially with a 900 ms timeout each, so one round on a 30-hop path with silent hops takes ~27 s past the nominal end.

### Data, history, gamer, capture

16. **The games-history "router ms" column is always empty.** `Gamer.cs:508,514` (`GameHistory.Minute`): declares `double gw = double.NaN;` and never assigns it; the line still writes `"," + F(gw)` as the 8th column. `GameHistory.Read` doesn't parse column 7 either. The per-minute router ping the file format promises is never recorded.
17. **A sequence restart is mistaken for a 16-bit wraparound, reporting ~99% loss.** `LiveCapture.cs:260` (`AddRtp`): `if (r.LastSeq >= 0 && seq < r.LastSeq && r.LastSeq - seq > 30000) r.Cycles++;`. A genuine wrap needs the old sequence near 65535; this only checks the gap. A sender restarting mid-call with a new random (lower) sequence inflates `MaxExt` by 65,536, so loss computes to ~99% and the MOS collapses for the rest of the session.
18. **New-device alerts stop forever once 30 MACs have *ever* been seen.** `Watch.cs:244` (`Devices.Check`): the pop-up is gated on `set.Count > 30`, where `set` is the cumulative known-MAC set loaded from `devices.txt` (never pruned, never expired). Phones rotate private MACs per network and over time, so a home network's set churns past 30 and the alert never fires again.
19. **Wi-Fi band/roaming advice matches access points by SSID only — a neighbour's (or evil twin's) AP is treated as yours.** `WifiAdvisor.cs:103,109`: the "switch to 5 GHz" and sticky-client checks never check BSSID/OUI, while the Twins check in the *same method* exists precisely because same-SSID, different-maker APs are a thing. Trigger: a neighbour uses your SSID with a 5 GHz AP at ≥40% → the app tells you to "Forget and rejoin", which can connect you to the neighbour's (or a twin's) AP. Same root cause in `LinkInfo.cs:540`.
20. **Neighbour wars counts any AP with my SSID as mine, even a different BSSID.** `AirLog.cs:29`: `Mine = string.Equals(b.Bssid, myB, ...) || (mySsid != "" && b.Ssid == mySsid)`. A neighbour (or evil twin) broadcasting my SSID is folded into "my network": excluded from crowding and winner math, never flagged as "moved onto your channel", and can skew "my channel/band".
21. **The packet journey's rewind ("Before") packets are never re-filtered to the discovered remote.** `Journey.cs:418` (`Session.Read`): after `FindRemote` discovers the far end, `now` is re-filtered but `before` (parsed while `F.Remote == ""`, i.e. any UDP on the local port or any ICMP) is used as-is. Trigger: a UDP flow whose far end isn't known, where the same local port also talked to another address in the last 20 s (previous match server, STUN) → the rewind section includes that other peer's packets, and the Explain rules run over a mixed stream.
22. **"Evenings with trouble" is computed with a different average than the one displayed.** `Gamer.cs:561` (`GameHistory.Week`): the bad-evening threshold uses `grp.Average(y => double.IsNaN(y.Avg) ? 0 : y.Avg)` (no-reply minutes count as 0 ms), while the week average uses `GameStat.Avg(...)` (NaN filtered). A server with many no-reply minutes gets its threshold average dragged down, so ordinary evenings get flagged bad.
23. **Video streams never get a clock rate, so they show as "media" with no jitter.** `LiveCapture.cs:264` (`AddRtp`): the rate estimate is a one-shot that only fires when the first 60 packets span >0.5 s. A video stream (120+ pps) gets 60 packets in <0.5 s, so `Rate` stays 0 forever: `Snapshot` labels it "media", shows jitter as "–", and computes MOS with jitter 0.
24. **"Capped by the receive window" ignores TCP window scaling.** `Journey.cs:332` (`TcpRules`): `double cap = maxWin * 8 / rtt / 1e6;` uses the raw advertised window. Window scaling is universal in modern TCP and the scale factor lives in the SYN's TCP options, which `Pcap.L4` never parses — so the cap can be wrong by the scale factor (raw 8,192 with scale 7 = real 1,048,576) and the finding can wrongly blame the window.
25. **The baseline counts silent minutes, so a never-answering gateway reads as "Normally 0 ms".** `Brain.cs:237-240,253` (`Baseline.Minute`): `b.Gw`/`b.Net`/`b.Loss` are only updated when non-NaN, but `b.N++` runs unconditionally, so N reaches 120 after 2 hours of *no* measurements; `Normal()` then prints "Normally 0 ms to your router and 0 ms to the internet". Worse, the alert at `:230-231` uses a 15 ms threshold against a 0 baseline, so the first answer over 15 ms fires "slower than usual" plus a notification claiming e.g. "40x slower than normal".
26. **Channel-overlap math ignores channel width.** `LinkInfo.cs:455-458` (`Overlaps`): 2.4 GHz is `|a−b| < 5`, anything else is `a == b`. An 80/160 MHz neighbour on channel 40 also covers 36–48, but `LeastCrowded` (`:247`), AirLog crowding, and the "sharing your channel" count all treat them as non-overlapping — while the width data is available (`Ap.Width`). Trigger: an 80 MHz neighbour on ch 40 → the app recommends ch 36 as "quietest" while the neighbour's signal covers it. (Note: `SelfTest.cs:964` pins exact-channel behaviour for 5 GHz, so a fix needs a width-aware overlap plus a self-test update.)

### Security, certs, crypto, policy

27. **OldTls reports an unreachable site as "TLS 1.0 / 1.1 refused" (green).** `SecChecks.cs:524`: both `SiteCert` calls return null when the site is down/DNS fails/443 is filtered → level 0 "refused". `e1`/`e2` are captured but never read. Contrast `CertExpiry()`, which reports level 3 "couldn't check" on null.
28. **SecFix has no branch for "certlm.msc" — the machine-roots fix link does nothing.** `FullView.Security.cs:60-68`: `SecFix()` handles only `ms-settings:`/`windowsdefender:`, `url:`, `shell:RecycleBinFolder`, and the `SecTools` list — `certlm.msc` is not in it. `SecChecks.cs:228` (`Roots()`) returns fix `"certlm.msc"` for the machine-roots row. Full enumeration confirms it's the only fix value with no handler. Trigger: click "Open the setting ›" on the machine-roots row — nothing happens, silently.
29. **RouterOld gives a green row to a router with only port 8080 or 22 open.** `SecChecks.cs:447,452,455`: `bad = open.Where(p => p[1] < 3)`; with only 8080 (or only 22) open the row is level 0 while its value reads "web (8080) open on 192.168.1.1" — the level-3 intent of those ports is ignored in the verdict.
30. **SmbSign reports "not required" on Windows 11 24H2, where signing IS required.** `SecChecks.cs:173`: reads `RequireSecuritySignature` (default 0) for both client and server. Microsoft made SMB signing required by default on 24H2 (Pro/Enterprise/Education, both directions), so an absent registry value means *required* — yet the check reports "not required when this PC opens shares" (level 3). The row's own advice text says "Windows 11 24H2 requires it by default", contradicting the value. (Mechanism checked in code; the 24H2 default is OS behaviour verified from Microsoft docs, not a live run.)
31. **Startup() never reads the 32-bit (WOW6432Node) Run keys.** `SecChecks.cs:266`: the registry loop uses `RegistryView.Registry64` for both CU and LM `…\CurrentVersion\Run`. A 32-bit program's autostart entry under `WOW6432Node\…\Run` is invisible — a false negative for 32-bit persistence.
32. **Startup() silently skips non-.exe autostart entries.** `SecChecks.cs:274`: `if (!exe.EndsWith(".exe") || !File.Exists(exe)) continue;`. A Run value pointing at a `.bat`/`.vbs`/`.ps1`/`.lnk` is never checked for a signature, while the row says "all .exe programs signed". Script-based persistence is never flagged.
33. **Pfx chain check ignores `X509Chain.Build()`'s return value.** `CertTools.cs:193-197`: the "Chain" row is derived only from the element count plus a self-signed test on the last element. `X509Chain` populates `ChainElements` with the partial chain on failure, so a chain that fails to build (an intermediate that did not actually sign the leaf, or a self-signed cert with a bad signature) can still be reported as "N levels up to a root" at level 0.
34. **Pfx "Key: present and usable" never checks the key matches the cert.** `CertTools.cs:171,185-187`: the header comment promises "is the key there and does it match", but the code only proves a private-key object loads. A PFX whose key and cert share an ID but are mathematically unrelated is reported "present and usable". Contrast `CertKeys.SameKey()`, which does compare public keys.
35. **WifiSec is dead on non-English Windows.** `SecChecks.cs:351`: parses `netsh wlan show interfaces` with the English-only regex `Authentication\s*:\s*(.+?)\s*$`. The codebase itself notes (OpenWifi comment) that "netsh's labels are translated", and `Monitor.ParseWifi` already handles German/Spanish. On French/German Windows the regex never matches → level 3 "not on Wi-Fi, or Windows doesn't show it" even while connected.
36. **Match() leaves the original self-signed cert behind while claiming "now one entry".** `CertKeys.cs:234-235`: `Match()` stores the CA cert + key as a *new* store entry and never removes the original self-signed cert; the row says "the CA's certificate and your key are now one entry in My keys". `Mine()` orders by FriendlyName and the new name is the old name + " (issuer)", so the leftover self-signed entry sorts first and My keys shows two entries for one key.
37. **Delete() removes the certificate but leaves the private key container.** `CertKeys.cs:351-359`: `X509Store.Remove` does not delete the key. Contrast `EcKeys.Delete()`, which deletes the key. After "Delete" in My keys the private-key material stays in the user's key store, orphaned and invisible to the app. (Fix needs CNG `NCryptDeleteKey`; there is no managed API for it in .NET Framework 4.8.)
38. **KillOthers() kills the --remove-folder uninstall helper.** `Program.cs:451-466`: `Single.Others()` matches any same-session process whose name starts with "AdeeboMeter"; `RunningIsOlder()` explicitly excludes names ending "-remove", but `KillOthers()` does not. Trigger: start AdeeboMeter while the uninstaller's "Removed" window is still open (helper waiting), the "already running but isn't answering … Close the stuck one and start fresh?" prompt appears, user clicks Yes → the helper is killed → the install folder is never removed.
39. **Mail() treats SPF "+all" as "SPF set" (green).** `SecChecks.cs:568-569`: an SPF record ending `+all` (authorises the entire internet to send as the domain) is reported level 0 "SPF set" when DMARC exists with p≠none.

### Cross-cutting

46. **About: "the 7-day history is off unless you switch it on" is wrong twice.** `FullView.Settings.cs:320` (AboutTrust): "The 7-day history is off unless you switch it on". History defaults **on** (`Program.cs:301`, `Cfg.History = true`, comment "history on by default") and default retention is **3 days** (`HistoryDays = 3`, `:303`), not 7. A false privacy claim in the app itself.
47. **Destination check Copy/Save text is systematically wrong.** `DestCheck.cs:41-47` (`DestResult.Text()`): (a) card rows lose their name — cards are 3-element `[name, value, level]`, but `Text()` does `r.Skip(r.Length > 2 ? 1 : 0).Take(2)`, printing `"value: level"` (e.g. a path row prints `"12 ms · loss 0%: 0"` instead of the hop); (b) **all Findings are silently dropped** — Findings rows are 2-element `[text, level]`, but `Text()` guards them with `if (r.Length > 2)`, never true, so the DNS second-opinion verdict, handover notes, double-NAT/CGNAT notes, MTU notes and firewall deductions are omitted from Copy/Save even though the code explicitly tries to include them.
48. **TWAMP: pressing Stop corrupts the "Reflected" verdict.** `Protocols.cs:480` vs `:451`: `int sent = n, got = res.Count, …` — but the send loop is `for (int i = 0; i < n && !run.Stop; i++)`. `sent` is never the number actually sent. 49. **Routing listen: Stop does nothing, and a quiet network captures twice.** `RoutingTools.cs:129-148` (`Listen`): never reads `run.Stop` — the tshark run (`Job.Run`, `(secs + 15) * 1000` timeout) runs to completion. Worse, `:148`: on a quiet network the first capture returns nothing, so it runs a **second full capture** before concluding "Heard nothing". Trigger: listen for 120 s, press Stop after 10 s — nothing happens until tshark ends; or listen on a quiet segment: 120 s input takes ~240 s of capturing to report nothing heard, while Duration says "120 seconds".
50. **"Works at home, not on VPN" guide can conclude "looks fine" while a VPN-route overlap is on screen.** `Investigate.cs:252-253,275,284`: `bad` is the first level-1 **or** level-2 row from `PathTools.Overlap()`, and it is observed (`r.Obs`), but the conclusion only handles the level-2 case. A level-1 "VPN route over your LAN" overlap (`PathTools.cs:203-206` — "Printers and other home devices may become unreachable while the VPN is up") falls through to `:284`: "The path to X looks fine from here…".
51. **STUN to an IPv6 server always reports "answered, but not with an address".** `Reach.cs:123` (`ParseStun`): only accepts family byte `1` (IPv4). An IPv6 `XOR-MAPPED-ADDRESS` (family 2, 20 bytes) is skipped, so `ParseStun` returns null and `Stun()` reports the server "answered, but not with an address". Trigger: STUN against an IPv6-only STUN server.
52. **IPv6 ping reports the wrong replying address.** `Icmp.cs:89` (`Echo6`): `Marshal.Copy(buf + 6, a, 0, 16)` — the reply is `ICMPV6_ECHO_REPLY`: a 28-byte `IPV6_ADDRESS_EX` (port 2 + flowinfo 4 with 2 bytes alignment padding + addr 16 + scope 4), then Status at 28, RTT at 32. The code reads Status at 28 and RTT at 32 and builds its own `dst` sockaddr with the address at offset 8 — but `From` reads at offset 6, i.e. 2 bytes of flowinfo + the first 14 bytes of the real address, last 2 bytes dropped (a reply from `fe80::1` displays roughly as `0:fe80::`). Consumer: `Lab.cs:150` in the ICMP sender lab ("Answered by …" rows).
53. **Key-backup restore decrypts into unbounded memory.** `EcKeys.cs:181-183` via `FileCrypt.cs:313`: `Decrypt()` dispatches on the first 8 bytes; for mode 3 (`EcKeys.IsBackup`) it calls `EcKeys.Restore(i, code)` with the raw `File.OpenRead` stream — no file-size check (the 200 MB `MaxCmsOpen` cap applies only to the `.p7m` branch) — and `Restore()` decrypts into a `MemoryStream`. A crafted/larger mode-3 file can exhaust memory.

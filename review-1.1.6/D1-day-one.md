# D1 - day-one user journey (AdeeboMeter 1.1.6 at 999a100)

How this was run: the r6 build would not start its main app under mono (Windows P/Invokes and private-font `GetHeight` throw), so I rebuilt 999a100 as `D1-day-one/d1.exe`. The only source change is a mono-only guard in `Theme.UiFamily` so the Barlow fonts come from fontconfig. Every Windows DLL the app imports is mapped through `AdeeboMeter.exe.config` to a stub library (`libshim.so`, generated by `gen.py`). Network APIs return "error" and user32/gdi32 return 0. Fonts: Segoe UI, Georgia and Consolas are aliased to DejaVu, and Nirmala UI to FreeSans (`fc/fonts.conf`).

Each journey ran under `xvfb-run` at 1366x768 in a fresh `$HOME`. The scripts are `fresh.sh` and `sc.sh`. Clicks were real X events from `click.exe` (XTest), and screenshots used `import`. Proxy variables were unset, so the machine was truly offline: no relay, ESPN or Bank of Canada was reached. The harnesses are in `D1-day-one/`:
- `mon.exe` logs the Monitor every half second and draws the widget card and chip.
- `judge.exe` runs Judge with a gateway but no samples.
- `walk.exe` opens every page, every Toolbox section and all 232 tools in en, fr, es, ar and bn.

Screenshots are `j*.png`, `m1-m4.png`, `mk.png`, `sp.png`, `pp.png`, `lar-home.png`, `lbn-home.png`, `j3m.png`, `un.png` and `wcards.png`.

Journeys covered:
1. Downloads with no settings: offer, Run here, Install, the first minute.
2. Portable, read-only (ro bind mount), and ar/bn/es/fr.
3. 1.1.5 settings (preset=engineer, no `mode`, 1.1.5 nav/views/tbview, fr) and the takeover logic.
4. Every page, tab, section and tool, with nothing measured yet.
5. Phone, Shell, Markets, Sports and Streaming offline.
6. Uninstall straight after install.

### 1. [day 1] Before anything is measured, Home and the widget say "All quiet. Nothing to fix - go get coffee." with a green OK
Severity: wrong result  
Where: src\Monitor.cs lines 853-895 (Judge: with every path level 3 the chain falls to the last `else Set(0, "All quiet. Nothing to fix...")`). Also src\Monitor.cs line 944 (BuildSnap: Chip "All quiet"), src\Ui\Theme.cs line 439 (Word: level 0 is "OK") and line 788 ("WAITING" exists but level 3 never reaches it).  
How to reproduce: `judge.exe d1.exe` builds a Monitor, sets only `Gateway = "192.168.1.1"`, calls Judge and BuildSnap. You get `L=0 path=0,3,3,3,3 chip=All quiet | All quiet. Nothing to fix - go get coffee.` On a real PC this is the state from second 1 until the first router and internet replies land. It lasts much longer where ICMP to the router or 1.1.1.1 is blocked (corporate networks), until the TCP fallback answers.  
What happens / what should happen: the very first thing a new user reads is a green verdict built from no data. The router and internet dots are grey ("?", "checking..."), but the headline, chip and pill all say fine. When nothing past the PC is known, it should say something like "Checking your connection..." (level 3 / neutral), as the "joining" branch already does for the no-gateway case.  
Confidence: confirmed (ran it: judge.exe; mon.exe timeline shows level 0 "All quiet" from 0 s with path 3,3,3,3,3)

### 8. [day 1] Upgrade trap: running 1.1.6 "from here" while 1.1.5 is installed takes over and starts as a brand-new user
Severity: wrong result  
Where: src\Program.cs line 78 (WriteDir: an exe in Downloads uses %LOCALAPPDATA%\AdeeboMeter, not the installed copy's settings), lines 195-203 (a newer copy asks the older running one to quit and takes the mutex), src\Setup.cs line 73 (offer), src\AppCtx.cs lines 261-268 (only an `autostart=` line means first start)

Confidence: suspected (traced through Main, ShouldOffer, WriteDir and LoadSettings; the takeover can't be shown under mono)

## Checked and held up

- **Offer card in Downloads, no settings:** shows Install / Just run it from here / "Remove it anytime"; nothing is written until a button is pressed (`j1a-6.png`).
- **Install:** writes `%LOCALAPPDATA%\Programs\AdeeboMeter\1.1.6\AdeeboMeter.exe` and a settings file with only `autostart=1`, so the installed copy gets the first-run setup. It also writes the Uninstall key (DisplayVersion, InstallLocation, UninstallString with `--uninstall`, NoModify/NoRepair) and the .adeebo association (HKCU only). It doesn't write the Run key itself; the installed copy does that on its first start. The Done card is honest (`un.png`).
- **Uninstall straight after install:** "Remove" stops others and removes the Uninstall key, the .adeebo classes, the Run value and the shortcut. It empties %LOCALAPPDATA%\AdeeboMeter, keeping keys-ec.txt, recipients and certs. The %TEMP% helper deleted the whole Programs\AdeeboMeter folder after exit, and RemoveFolder's guard (not inside Base, key gone) passed. The helper exe stays in %TEMP% until the next start, by design (`j8a-*`, `un.png`).
- **Portable copy (`AdeeboMeter.portable`, outside Downloads):** no offer; data goes to `data\`, settings and log beside the exe. Next to a Downloads exe the marker is ignored, by design.
- **Read-only folder (ro bind mount) with the portable marker:** no crash; settings, log and history fall back to %LOCALAPPDATA%\AdeeboMeter (silently - acceptable).
- **1.1.5 settings (preset=engineer, no `mode`, wifi=10, tbview=q, 1.1.5 nav "home,stream,trade,toolbox,time,learn", views=engineer~..., lang=fr):**
  - Engineer becomes Balanced with Balanced timings, and Mode becomes "pro".
  - The view is kept ("Vue Ingénieur").
  - Nav becomes home,toolbox,stream,sports,trade,time,learn: Sports added once, Toolbox second.
  - Toolbox starts on All tools (intended, tbview2).
  - Old points.txt and history formats load: points.txt only gained a bound (Points.cs), and History.cs only gained the .packing and cap changes.
  - No UI error or Fatal on Windows-relevant code.
- **Every page, every Home tab, the 6 Toolbox sections and all 232 tools opened (not run):** fresh state, en/fr/es/ar/bn (walk.exe), no exceptions. The one UI error is mono's `SystemInformation.PowerStatus` NotImplemented on Outlook.
- **Empty states that tell the truth:**
  - Time machine: "Nothing recorded for this day yet - history writes one line a minute".
  - Gamer: the "Pick a game to watch / nothing is sent... until you do" card.
  - Streaming: "Streaming is switched off".
  - Markets currencies: "Turn on".
  - Markets offline after Turn on: "Couldn't reach the Bank of Canada yet - nothing to show until it answers. It tries again in 5 minutes."
  - Weather: off until a place is typed.
  - Live capture: "Needs Wireshark (tshark) and Npcap - not found on this PC" with Start disabled.
  - Shell first prompt: banner, scripts list, status line, no error.
- **No network contact without a click on Markets/Sports/Streaming/Weather first load.** Each source has its own Turn on - the exception is #3.
- **The first-minute monitor run (mon.exe):** the first verdict comes at about 2 s, and no exception in 22 s.

### Distinct "UI error" / "Fatal" lines seen (all mono-only, not reported as findings)

- `UI error: System.NotImplementedException ... XplatUIDriver.get_PowerStatus ... FullView.PaintOutlookBody`: Home/Outlook paint. Mono has no SystemInformation.PowerStatus; .NET does.
- `Fatal: System.ObjectDisposedException: Safe handle has been closed at NativeEventCalls.SetEvent ... Socket.BeginConnectCallback`. This comes from the `using (var wh = ar.AsyncWaitHandle)` timeout pattern in Gamer.TcpMs (src\Gamer\Gamer.cs line 615) and Toolkit.ConnectWithin (src\Checks\Toolkit.cs line 81) when a connect finishes after the timeout. It killed the mono process 4 s after start with `gmon=valorant`, offline. .NET Framework's LazyAsyncResult swallows ObjectDisposedException on Set, so it should hold up there. Worth a real-PC check with a watched game and the cable out.
- `Fatal: EntryPointNotFoundException DestroyIcon / CreateCompatibleDC` and `ArgumentException FontFamilyNotFound (Menus.Row.set_Line → Font.GetHeight)`: the harness before the DLL stubs and fonts were in place.
- `window froze (3 s so far) while timer on trade`, the first time Markets was turned on. This is most likely mono's `TimeZoneInfo.FindSystemTimeZoneById("Eastern Standard Time")` failing slowly on Linux (Trading.EasternNow, called from paint), so it isn't reported. On Windows the id exists and Program.Main pre-warms it.
- Markets › World markets shows every exchange "Closed" under mono, from the same time-zone id; not reported.

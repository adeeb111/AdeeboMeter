Inside your provider

OSPF and IS-IS - the map inside one network

Every router knows the whole map of its own network, and the shortest way across it.

Inside one provider, routers run a link-state protocol - OSPF or IS-IS - so each one holds the same map of all routers and links, with a cost on each link.

How the conversation goes

Router ARouter B

  1. Router A to Router B: Hello - I'm A, area 0

  2. Router B to Router A: Hello - I see you

  3. Router A to Router B: here is my whole link database

  4. Router B to Everyone: my link to C just went down (new LSA)

  5. Every router → Itself: run shortest path again, update the routes

When it goes wrong

Two routers that disagree on timers, area or MTU never become neighbours, and part of the map goes missing. A flapping link makes every router recompute again and again - the network "churns".

Going deeper

Every router floods small notices about its own links (OSPF's LSAs, IS-IS's LSPs). Each then runs Dijkstra's shortest-path algorithm on the full map. When a fibre is cut, the routers at each end flood the change and every router recomputes - in well-tuned networks, well under a second, and fast-reroute backups are often ready before that. BGP decides which exit to use; OSPF or IS-IS find the way to that exit. Big providers often prefer IS-IS: it runs directly on the link layer, not over IP, and copes well with very large single areas. OSPF splits big networks into areas around a backbone area 0.

Mobile, LTE and 5G

The 5G core: AMF, SMF, UPF and friends

Separate small functions that call each other over HTTP APIs.

The AMF handles registration and mobility; the SMF sets up your data session; the UPF carries your packets; AUSF and UDM check who you are; the NRF is the directory where functions find each other.

How the conversation goes

gNodeBAMF

  1. gNodeB to AMF: registration request (N2)

  2. AMF → AUSF: authenticate this subscriber (N12)

  3. AMF → SMF: create a PDU session (N11)

  4. SMF → UPF: set up the forwarding rules (N4)

  5. UPF → Internet: your packets (N6)

When it goes wrong

AMF trouble: phones can't register. SMF or UPF trouble: registered, no data. A failover that keeps registration but drops sessions looks exactly like "full bars, no internet" until the phone re-establishes its session.

Going deeper

The 5G core is "service-based": functions expose HTTP/2 APIs on a shared bus (N11 between AMF and SMF, N12 to the AUSF, N8 and N10 to the UDM). The gNodeB talks to the AMF over N2 (NGAP, with NAS inside) and sends data to the UPF over N3 (GTP-U); the UPF reaches the internet or a company network over N6. The SMF programs the UPF over N4 (PFCP). Because functions are software, they run in clouds with several copies; when one fails, another takes over - and a test of that failover asks one question: how long until data works again? The PCF sets policy; network slices let one core run separate virtual networks with different rules.

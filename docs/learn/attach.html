How a phone joins: LTE attach and 5G registration

Who are you, prove it, here's your address.

Joining has two halves: registration (who you are, proven with the SIM's key) and a data session (an IP address and a path). In 4G the default bearer comes with the attach; in 5G the PDU session is a separate step.

How the conversation goes

PhoneAMF

  1. Phone to AMF: Registration Request

  2. AMF to Phone: Authentication Request (challenge)

  3. Phone to AMF: Authentication Response

  4. AMF to Phone: Registration Accept

  5. Phone to AMF: PDU Session Establishment Request (DNN internet - passed on to the SMF)

  6. AMF to Phone: PDU Session Establishment Accept from the SMF - IP 100.70.3.9

When it goes wrong

"Registered" on the router's screen only means the first half worked. Look for the session accept and an IP address before blaming anything else.

Going deeper

In 4G: attach request → authentication (the network sends a challenge only your SIM can answer) → security mode → the MME asks the gateways for a session → attach accept with your IP → the default bearer is up. In 5G SA: registration request → authentication → security mode → registration accept; then the phone asks for a PDU session for a DNN (5G's name for the APN) → the SMF picks a UPF and an address → PDU session accept. Each step can be rejected with a cause code (for example "DNN not supported", "insufficient resources"). A modem log that ends after "PDU Session Establishment Request" with no accept or reject is a strong clue the problem is the session side, not the radio.

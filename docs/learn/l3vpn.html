L3VPN (VRF) - a private network inside the provider

Many companies on one provider network, each in its own walled routing table.

An enterprise connects its offices through the provider. The provider edge keeps a separate routing table per customer (a VRF - virtual routing and forwarding), so overlapping private addresses never mix.

How the conversation goes

Branch routerPE-Branch

  1. Branch router to PE-Branch: OSPF - I have 10.20.0.0/16

  2. PE-Branch → Route reflector: MP-BGP - RD 64500:7 10.20.0.0/16, label 22, target "Acme"

  3. Route reflector → PE-Head office: the same route

  4. PE-Head office → Head-office router: 10.20.0.0/16 is reachable through me

  5. Head office → Branch: traffic, carried with VPN label 22

When it goes wrong

A route-target typo means a branch silently can't see head office. Overlapping addresses are fine inside separate VRFs and break the moment two are joined.

Going deeper

Customer routes are learned at each site (static, OSPF or BGP), then carried between provider edges by MP-BGP as VPN-IPv4 routes: the customer's prefix plus a route distinguisher to keep it unique, plus route targets that say which VRFs import it - that's how a hub-and-spoke or a shared-services VPN is built. In the core the traffic rides MPLS (or segment routing / SRv6) with an inner VPN label. Internet access for the same company is often just another VRF. EVPN is the same idea for Ethernet (layer 2) services and data-centre fabrics.

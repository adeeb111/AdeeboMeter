আপনার ইন্টারনেট সেবাদাতার নেটওয়ার্কের ভেতরে

MPLS: কোর নেটওয়ার্কে লেবেল দেখে প্যাকেট পাঠানো

প্যাকেটের সামনের ছোট লেবেলটি বলে, এরপর সেটি কোথায় যাবে।

সেবাদাতার নেটওয়ার্কে ঢোকার সময় প্যাকেটে লেবেল বসে। কোর রাউটারগুলো আগে ঠিক করা পথ (LSP) ধরে শুধু লেবেল বদলায়। ভেতরের IP ঠিকানা পড়তে হয় না।

কীভাবে বার্তা আদান-প্রদান হয়

গ্রাহকের রাউটারসেবাদাতার এজ রাউটার PE1

  1. গ্রাহকের রাউটার থেকে সেবাদাতার এজ রাউটার PE1-এ: 10.2.0.9 ঠিকানার জন্য IP প্যাকেট

  2. PE1 → কোর P1: লেবেল 300 (পথ) + লেবেল 17 (গ্রাহকের VPN) + প্যাকেট

  3. P1 → P2: লেবেল 410 + 17 + প্যাকেট (বাইরের লেবেল বদলেছে)

  4. P2 → PE2: লেবেল 17 + প্যাকেট (বাইরের লেবেল খুলে ফেলা হয়েছে)

  5. PE2 → গ্রাহকের সাইট B: 10.2.0.9-এর জন্য IP প্যাকেট

সমস্যা হলে কী হয়

প্রতি লেবেলে 4 বাইট যোগ হয়। সেই বাড়তি অংশের জন্য কোরের MTU না বাড়ালে বড় প্যাকেট বাদ পড়ে। সেবাদাতার ভেতরে তখন MTU black hole তৈরি হয়।

আরও বিস্তারিত

LDP লেবেল বরাদ্দ করে। এখন অনেক নেটওয়ার্কে IGP-তেই লেবেল যায়, যাকে segment routing বলে। প্যাকেটে একাধিক লেবেল থাকতে পারে। বাইরেরটি কোরের ভেতরের পথ জানায়, আর ভেতরেরটি জানায় প্যাকেটটি কোন গ্রাহক বা সেবার। ভেতরের লেবেলের কারণেই একই নেটওয়ার্কে আলাদা VPN, Ethernet সেবা ও ট্র্যাফিকের পথ নিয়ন্ত্রণ করা যায়। শেষের আগের রাউটার সাধারণত বাইরের লেবেল খুলে ফেলে, যাতে শেষ রাউটার শুধু সেবার লেবেল দেখে। MPLS-এর মধ্যে ট্রেসরুটে ICMP extension দিয়ে লেবেলসহ হপ দেখা যেতে পারে। সেবাদাতা টানেলে নিলে হপগুলো আড়ালেও থাকতে পারে।

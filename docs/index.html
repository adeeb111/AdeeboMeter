Design

Five promises the whole design follows

¢

A penny app

A few dozen tiny jobs a minute. Anything heavy runs only while you look at it, and stops by itself.

◎

Never listens

No server, account or update check. It checks at every start that it opens no listening port.

✓

No admin rights

Only what Windows shows a normal user. If Windows says no, that part simply doesn't show.

{}

Every message has a friendly and a plain version. The fix always comes right after the joke.

AdeeboMeter · Theory of Everything06
The heart · Monitor

Two threads do all the watching.

Sampler — every second

  • CPU, memory, disk and network bytes
  • TCP/IP health: retransmits, resets, failed connections, unreachables, UDP drops
  • Every 10 s it judges: OK / Busy / Act, and one sentence
  • Optional: one line to today's 7-day history file

Probe — every 2 to 10 seconds

  • Router ping · internet + DNS check (cache skipped)
  • Adapters, VPN, DNS server, MTU — changes become events
  • Gateway spoof watch: the router's MAC must not change
  • Wi-Fi signal, roams, drops — and Windows' reason for a drop
  • Apps and connections · Teams calls get the fast pace

Check a destination

Eight steps, from the name to the last hop.

1

DNS

Real lookups, cache skipped. A second opinion from 1.1.1.1 catches filters.

2

Route

Which adapter Windows would use — found without sending anything.

3

Ping

Four echoes: delay and loss.

4

TCP

The three-way handshake to your port, timed.

5

TLS

1.2 / 1.3 only, Windows validates. Untrusted? Nothing is sent.

6

HTTP

One HEAD request: status line and time to first byte.

7

Path MTU

"Don't fragment" pings find the biggest packet that fits.

8

Path

MTR-style trace: 3 rounds per hop, all hops at once.

If a check fails, a sign-in page check catches hotel and airport portals. Pin up to 5 destinations and Run all.

AdeeboMeter · Theory of Everything12
The path story

Who carries your traffic — and what's in the way.

NAT

Double NAT and carrier-grade NAT (100.64.x.x) spotted from the hop addresses.

Tunnels

From the packet size: 1492 = PPPoE; smaller = VPN, LTE or satellite.

Firewalls

A refusal faster than the server is far = something in between said no. Ping works, port silent = dropped.

And more

Load-balanced hops, where the delay jumps, silent routers (normal), the return path from reply TTLs.

AdeeboMeter · Theory of Everything15
Security

Hardened by design, proven by checks.

No shell, ever

Windows tools by full System32 path, fixed arguments, a timeout, inside a job object that dies with the app.

Inputs validated

Destinations checked strictly before anything runs. Capture paths fenced inside AdeeboMeter's own folder.

TLS done right

Only TLS 1.2 / 1.3; Windows validates certificates; nothing is sent over an untrusted connection.

DLLs only from System32

A defence against DLL planting.

No risky parsing

No binary serializers, no XML parser, no secrets in the code, no home-made crypto.

Static analysis: 0 findings

Builds clean against Microsoft's .NET security and quality analyzers with every rule switched on.

AdeeboMeter · Theory of Everything18
Honest limits

What Windows doesn't let us do without admin or the cloud.

AS numbers / BGP data

Need an internet service or a database — left out on purpose. Router names tell "who carries my traffic" instead.

TCP / UDP traceroute

Needs raw sockets (admin) — traces use ICMP.

Per-connection RTT

Needs admin to switch on — per-app traffic comes from live capture instead.

The DNS cache

Admin-only on some Windows builds — then names come from live capture.

Speed tests

Would need a server or a listening port — not offered.

Inside a tunnel or your ISP

Can only be inferred, never seen.

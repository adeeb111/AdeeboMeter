Send the file. Keep the code separate.

Before sending a document, turn it into an encrypted file. Give the recipient the unlocking code another way. The file operation can happen on your device, without uploading its contents.

  • Phone and PC
  • 3 min read
  • Reviewed 27 November 2026

Try it with a small test file first

  1. Open Files over HTTPS in a browser that supports Web Crypto. Choose the file in Lock a file.
  2. Save the resulting .adeebo file and keep the generated code. The tool does not keep a recoverable copy of that code for you.
  3. Send the encrypted file. Pass the code through a separate channel, such as a call rather than the same email.
  4. Ask the recipient to open and verify the result before relying on the workflow.

What encryption does it use?

LayerCurrent code-protected format
File encryptionAES-256 in CBC mode.
Tamper detectionHMAC-SHA256 over the header and ciphertext, using a separate key.
Keys from the codePBKDF2-HMAC-SHA256, with 600,000 iterations for newly created files.
Per-file randomnessA fresh salt and initialization vector.

AES is a published standard, not an AdeeboMeter invention. CBC needs authentication alongside it; the .adeebo code format includes a separate HMAC. These algorithm names describe the construction. They do not make the app independently audited or certified.

How hard is it to break?

For a uniformly random 256-bit AES key, there are 2256 possible keys. Exhaustive key search is not a practical recovery plan. But that number is not the effective strength of every encrypted file: attackers may target the code, implementation or device instead.

  • Keep the generated random code.A short, predictable replacement would be easier to guess. PBKDF2 adds work to each guess; it cannot rescue a weak secret.
  • Protect both endpoints.Malware, a screenshot of the code or an unlocked decrypted copy can bypass the need to attack AES.
  • Keep a recovery plan.There is no code-reset account or built-in recovery service for a lost sharing code.
What this does not hide

Encryption does not erase the original or downloaded decrypted copy. A transfer service can still see an attachment’s outer name, size and delivery details. Keeping the file content local during encryption does not mean the surrounding website makes no requests for its pages or assets.

Know the current size and compatibility limits

The browser tool caps input at 100 MiB on phones and devices it identifies as low-memory, or 300 MiB otherwise. It processes the file in memory, so a smaller file may still fail on a constrained device. The Windows code-protected .adeebo path supports streaming files up to 4 GiB.

The format is specific to AdeeboMeter: changing the extension to .zip does not make it a password-protected ZIP. For a recipient who needs a standard format, agree on a compatible tool before sending.

The code is part of the delivery.

Keep the generated code, send it separately, and confirm the recipient can open a test file. Strong encryption is useful only when the whole handoff works.
